# 学习者画像与资源难度适配度测试方案（修订版 v0.2）

> 原稿：`测试方案分支/学习者画像与学习资源难度适配度测试方案_初稿.docx`
> 保留：9 类画像（3×3）、每类 10 人共 90 用户、LLM Rubric 4 维、问题类别表（都很好）
> 修订：加硬门槛、加客观指标、判定防放水、补动态反馈测试、样本口径写清

---

## 1. 指标定义（对齐赛题 ≥85%）

```
适配准确率 = 判定为"适配"的用例数 / 有效用例总数   （目标 ≥85%，Wilson 95% CI）
1 组用例 = 1 个画像 × 1 个目标知识点 × 1 次推荐（Top3）
```

- 90 用户 × 每个用户 3 个知识点 = **270 组用例**（≥50 组，满足赛题）
- 有效用例 = 系统成功返回 Top3 推荐且资源库有该知识点的用例

## 2. 判定标准（双通道）

**通道1 客观比对（确定性，优先）**：Top3 推荐资源的 `difficulty` 标签
是否落在画像目标难度区间（低[1,2]/中[2,3]/高[3,4]）。
- 命中 ≥1 个资源在目标区间 → 客观适配 ✓
- 资源缺难度标签 → 该用例降级为"主观通道"并记录缺失率

**通道2 LLM Rubric（保留原 4 维评分）**：
术语 25% / 前置知识 35% / 密度时间 20% / 形式 20%，1-5 分。
- **新增硬门槛**：任一维度 <3 分 → 直接"不适配"（防止时间/形式维度被权重稀释掩盖）
- 无硬门槛违规且均分 ≥4 → 适配；3.0~3.99 → 基本适配（算不适配，需优化）；<3 → 不适配

**合并**：通道1 或 通道2 判"适配"→ 适配；都判不适配 → 不适配；冲突 → 人工复核。
**人工抽检 10%**，自动 vs 人工一致率 ≥95%。

## 3. 画像与用例设计（沿用原稿）

- 9 类画像 P1~P9（专业背景低/中/高 × 前置掌握度低/中/高），每类 10 人
- 每类内部交叉：15/30/60 分钟时间预算、3 种资源偏好、不同历史正确率
- 每个用户选 3 个目标知识点（覆盖方剂学/中药学/中医诊断学等 ≥3 个科目）
- 画像通过 `ReviewCardRequest.user_profile` / `user_knowledge_state` 注入（真实字段，已确认）

## 4. 稳定性测试（新增）

- 随机抽 30 组用例，同输入跑 3 次
- 报告推荐结果一致率（Top3 重合度）；波动 >30% 的画像类型标记"系统性不稳定"

## 5. 动态反馈测试（新增，直击赛题"交互反馈→动态决策更新"闭环）

- 模拟用户连续答对 3 次 / 连续答错 3 次，检查系统是否相应提高/降低后续资源难度
- 指标：难度调整方向正确率（应 ≥80%）
- 这是"作品完整性 30 分"里动态决策更新的直接证据，建议必做

## 6. 局限说明（保留并强化）

- 前置知识掌握度为模拟输入（无独立前测模块）→ 报告中说明，并用历史答题数据（question_attempt）支撑
- 真实用户长期跟踪实验列为后续工作

## 7. 执行

```powershell
# 脚本位置：evaluation_delivery/（codex2.py 骨架，按本方案参数化）
python codex2.py --profiles 9x10 --kps 3 --judge deepseek --objective-first
```

预估：270 组 × 全链路 ~2.5min ÷ workers 3 ≈ 4 小时 + Rubric judge 1 小时。
