# 上传处理收敛：第二阶段

## 实现范围

本阶段统一任务进度视图，并为原本仅存于内存的教材任务增加持久化。现有接口、教材与考纲产物、题库审核和激活规则保持不变。

### 教材任务

- `services/upload_tasks.py` 将任务元数据原子写入业务 runtime 的 `upload_tasks/<owner哈希>/`；响应不包含 owner、内容指纹和文件路径。
- 上传、查询、历史列表均使用登录用户身份，其他用户的任务返回404，未登录返回401。
- 同一用户、相同文件与选项复用未失败或结果不确定的任务，避免重复执行；已确认处理失败且允许重试时建立新任务，旧记录保留。已完成的相同请求也复用原结果。
- 进程执行锁与用户提交锁防止并发重复提交；回调写入采用原子替换，完成后迟到进度不会覆盖终态。
- 正常关闭等待上传结束，不将取消传播给正在发布的后台工作。硬终止后，查询失去执行锁的运行任务会标记 `UPLOAD_INTERRUPTED`，禁止自动重放。
- 中断状态不意味着业务资料一定未写入；必须先核实书架。当前没有自动修复、自动续跑或强制重试接口。

现有 `POST /api/v1/textbooks/import` 和 `GET /api/v1/textbooks/import/{task_id}` 保留原状态字段并附加进度信息；新增 `GET /api/v1/textbooks/imports` 提供当前用户历史（默认50，最多100）。

### 统一进度合同

`contracts/upload.py` 提供 `UploadProgress`，包含任务ID、类型、统一状态、源状态、阶段、说明。只映射系统固定枚举，不根据用户文本判断业务，不虚构处理百分比。

| 业务 | 唯一状态来源 | 进度附加位置 |
| --- | --- | --- |
| 教材 | 新持久任务文件 | 上传响应、状态查询、历史列表的 `progress` |
| 考纲 | 原 manifest 文件 | 列表条目和详情 manifest 的 `progress` |
| 个人题库 | 原数据库导入任务 | 上传响应、列表和详情的 `progress` |
| 管理员审核 | 原数据库审核任务 | 任务列表和详情的 `progress` |

个人题目 `preview_ready` 与 `needs_human_review` 统一映射为 `needs_review`，不误报为可直接练习。管理员 `completed` 表示处理流程结束，是否发布仍以原审核结果字段判断。考纲进度在读取时生成，不写回manifest，不增加第二套状态。

## 未覆盖边界

- 本阶段未迁移历史内存教材任务，重启前已丢失的ID无法凭空恢复。
- 文件锁要求Linux本地文件系统或具备可靠锁语义的共享存储，不宣称支持独立磁盘上的多机队列。
- 已完成任务长期保留；相同请求返回原结果。教材后续删除或人工修复后的重新导入策略需与相应管理接口一起设计。
- 考纲和个人题库仍沿用原执行生命周期；仅统一进度投影，不宣称已解决它们所有崩溃恢复问题。
- 正式个人知识完整外置导入流程、公共索引、旧RAG不在本阶段改造范围。
- 现有前端尚未使用新增历史接口或统一进度视图；页面收敛属于第三阶段。
- 第一、二阶段均未部署，本阶段未运行Live上传或修改生产业务数据。

本地变更前精准备份：`/tmp/upload-phase2-before-20260909.tgz`。回滚仅恢复本阶段涉及文件并移除本阶段新增文件，不全树覆盖，不改存量业务产物。回滚到内存实现后，新任务元数据仍可保留，但旧代码不会读取这些历史记录。
