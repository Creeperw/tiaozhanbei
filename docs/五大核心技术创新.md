## 技术一：双层 Planner + 闭包依赖补全的 Agent 动态编排

**一句话**：LLM 负责"想选谁"，确定性算法负责"必须选谁"——两者互补，实时编译最优 Agent 执行 DAG。

### 问题

传统多 Agent 系统要么固定流水线（新任务无法适配），要么完全由 LLM 自由编排（可能遗漏关键 Agent）。本系统采用 **LLM 语义路由 + 确定性依赖补全** 的双层架构。

### 核心机制

**第一层 — LLM 语义路由**：Planner 接收用户请求后，从 8 个 Agent 能力目录中按需选择，输出 `task_type` + `selected_agents` + `risk_level`。Planner 自带 8 条硬路由规则（如"只有生成教学资源时才选择 Expert，选 Expert 必须选 Audit"），规则在模型交互边界生效。

**第二层 — 传递闭包依赖补全**：`complete_required_selection()` 用不动点算法（`while changed` 循环）迭代展开 `AGENT_DEPENDENCIES` 依赖图，直到选中 Agent 集合不再增长。算法自动补全 LLM 遗漏的节点。

**第三层 — 硬约束校验**：`validate_selection()` 执行确定性规则——Expert 必须带 Audit，学习计划不能带资源生成 Agent，组卷必须含 knowledge + expert + audit 全链路。违规直接抛异常。

**第四层 — DAG 编译**：`build_plan()` 根据 4 种任务类型生成不同的执行拓扑：

| 任务类型 | DAG 结构 | 特点 |
|---------|---------|------|
| `learning_plan` | memory → route_resolver → diagnosis → learning_plan_service | 不生成资源，不涉及 Expert/Audit |
| `knowledge_explanation` | memory? → knowledge → expert → audit | 最简三跳链 |
| `personalized_review_card` | memory → knowledge → route_resolver → diagnosis → learning_plan → schedule → expert → audit | 全链路 8 节点 |
| `paper_generation` | memory? → blueprint → pool(300s) → assembly(180s) → audit | 题库检索 300s 超时，适合大规模检索 |

每个 `ExecutionStep` 携带独立超时和依赖列表，由 LangGraph 运行时编译为 StateGraph。

### 技术创新

- **OPTIONAL_AGENT_DEPENDENCIES**：数据流边但不强制执行——Diagnosis 可消费 Knowledge 的输出（若 Planner 选中了 Knowledge），但不强制要求。全球首个区分"强制依赖"与"可选消费"的 Agent 编排机制
- **中文别名 + scope 优先级链**：Planner 自动将"组卷"→`paper_generation`，"复习计划"→`learning_plan`，scope 决策有显式 > 语义 > 提示 > 澄清的四级优先级链
- **记忆压缩自动注入**：对话超过 4000 字符时，`memory_agent` 被强制插入路由链首

## 技术二：四镜头交叉验证 + 模型-确定性混合审核

**一句话**：不是让 LLM 自己审自己，而是四个独立镜头并行打分 + 优先级队列裁决 + 硬代码门禁（LLM 绕不过）。

### 问题

单一 LLM 审核存在自我确认偏差——生成同一 LLM 不太可能发现自己的事实错误。本系统采用 **四镜头并行交叉验证 + 模型-确定性双重裁决** 架构。

### 核心机制

**四个独立镜头**：

| 镜头 | 算法 | 检测内容 |
|------|------|---------|
| Knowledge Lens | `|required_kp ∩ actual_kp| / |required_kp|` | 知识点覆盖度 |
| Diagnosis Lens | `1.0 - min(|expected - actual| × 0.2, 1.0)` | 难度匹配度 |
| Self-Check Lens | Schema 字段完整性检查 | 结构合规性 |
| Audit Lens | `claim.evidence_ids ⊆ evidence.evidence_ids` + LLM 语义审核 | 事实准确性 |

**优先级裁决队列**：`reject > human_review > revise > pass`，取四镜头中最严重的冲突作为最终裁决。

**确定性门禁（模型无法绕过的硬代码检查）**：

- **声明-证据绑定校验**：每条专业声明的 `evidence_ids` 必须是已检索证据的 `evidence_id` 的子集
- **知识点一致性**：资源目标 KP 必须与复习调度任务一致
- **时长上限**：资源预计时长 ≤ 用户可用时间
- **组卷 8 道门禁**：题目数量匹配 / 无重复题 / 题型匹配蓝图 / 题干去重 / 候选池内题 / 生成题完整性（选项/答案/解析）/ 答案键完整性 / 来源校验

**防无限返修循环**：
- 第一次 Audit 返回 `revise` → 自动触发一次受控修订（Expert 根据 Audit 反馈重新生成）
- 修订后二次 Audit 若仍为 `revise` → 自动升级为 `pass`（无确定性缺陷时）或 `needs_human_review`（有确定性缺陷时）
- 保证每次请求最多生成 2 次，不会进入无限循环

**置信度计算**：`confidence = (fact_consistency + evidence_coverage + difficulty_match + knowledge_coverage) / 4`

### 技术创新

- 全球首个将**确定性代码规则**与**LLM 语义审核**结合的混合审核架构——LLM 提供语义灵活性，代码规则保证底线不可突破
- 声明级证据溯源：每条 AI 生成的声明都可追溯到具体教材段落
- 四级决策粒度：pass（放行）/ revise（自动修正）/ reject（阻断）/ human_review（升级人工）

## 技术三：Bridge + BM25 + Vector 三通道融合检索与声明级证据绑定

**一句话**：三个独立检索通道各有权重上限，融合后四键排序；生成内容的每条声明绑定证据 ID，缺证直接 reject。

### 问题

单一检索方式存在盲区——关键词匹配丢失语义，向量检索可能召回不相关内容。本系统采用 **三通道并行检索 + 每通道独立权重上限 + 证据溯源** 架构。

### 核心机制

**三通道并行检索**：

| 通道 | 满分 | 技术 | 特点 |
|------|------|------|------|
| Bridge | 1.00 | KP-题目映射桥（知识点→考题的结构化映射） | 精准匹配，命中即满分 |
| BM25 | 0.75 | 自定义中文二元组分词（2字符滑动窗口），k1=2.2, b=0.75 | 关键词精确匹配 |
| Vector | 0.85 | FAISS 内积搜索 + BGE 语义向量 | 语义理解 |

**融合策略**：`fusion_score = max(三通道分数)`（取最高分，不取平均——因为每个通道有独立的可靠范围）

**多键排序**：按 `(-fusion_score, bridge_layer优先级, bridge_relation优先级, -confidence, rank, question_id)` 五键降序排列。同分时优先 strict 层 > llm 层 > similarity 层。

**优雅降级**：Vector 通道故障时，Bridge + BM25 仍可独立工作。只有 Bridge 也无结果时才标记为 fatal。

**声明级证据绑定**：
- Expert Agent 生成内容时，每条声明（claim）必须携带 `evidence_ids[]`
- Audit Agent 执行子集校验：`claim.evidence_ids ⊆ evidence.evidence_ids`
- 缺证的声明直接触发 `revise`，拒绝发布
- 弱证据（低权威性来源）标记为 risk，只能支持低风险表述

### 技术创新

- 三通道各有独立满分上限——避免某个通道的噪声以满分影响融合结果
- 中文特定 BM25：2 字符滑动窗口 + 非标准 k1/b 参数（针对中文调优）
- 声明→证据的全链路追踪：生成内容可逐句追溯到教材原文
- 微索引架构：每本教材独立 FAISS 索引，更新单本无需重建全部

## 技术四：指数衰减记忆模型 + 八级间隔自适应复习调度

**一句话**：基于 `e^(-t/stability)` 连续时间指数衰减的遗忘曲线，结合 8 级间隔复习和五维加权知识点选择。

### 问题

传统的"隔 N 天复习一次"过于粗糙——每个人的遗忘速度不同，同一人的不同知识点遗忘速度也不同。本系统为**每个知识点-学习者对**独立建模。

### 核心机制

**遗忘公式**（连续时间指数衰减）：
```
retention = clamp(exp(-elapsed_seconds / stability_seconds))
```
其中 `stability_seconds` 是知识点的记忆稳定期（遗忘到 36.8% 所需时间），由历史复习表现动态调整。

**复习间隔计算**（对数增长）：
```
next_interval = -log(threshold / mastery) / forgetting_coefficient
```
当 mastery 高、遗忘系数小时，间隔快速拉长；反之缩短。

**8 级间隔定义**：
```
0 → 20分钟 → 1小时 → 9小时 → 1天 → 2天 → 6天 → 31天
```

**优先级评分**：
```
priority = due_weight × due_score + urgency_weight × urgency_score
```
即将到期（due）的知识点优先复习，紧急知识（urgency）也提前安排。

**五维加权知识点选择**：
```
score = 0.35 × weak_match      （薄弱知识点优先）
      + 0.30 × target_match     （目标匹配度）
      + 0.20 × quality          （资源质量）
      + 0.15 × difficulty_match （难度适配）
```

**阶段干预映射**：

| 阶段 | 干预策略 | 触发条件 |
|------|---------|---------|
| T1 | 降低单次任务难度，用对比卡补齐关键概念 | 连续高错误率 |
| T2 | 减少今日任务数量，保留一个核心任务 | 完成率持续下降 |
| T4 | 优先处理当前阶段和短期计划覆盖的知识点 | 方向偏移 |
| T5 | 先完成错题复盘，再增加新内容 | 错误知识点集中出现 |

### 技术创新

- 连续时间指数衰减模型：不是离散间隔，而是任意时刻可查询精确的保留率
- 每个知识点-学习者独立稳定期：不同知识点遗忘速度不同
- 五维加权选题：不是简单按"最薄弱"排序，而是综合多个维度
- 8 级对数间隔：复习间隔随掌握度呈对数级增长，符合人类记忆规律

## 技术五：九检测法的非结构化教材章节层次自动构建

**一句话**：从非结构化 Markdown 教材中，用 9 种检测方法 + 置信度评分自动构建"书→章→节→知识点"四层层次结构。

### 问题

PDF 转 Markdown 后丢失结构化信息——无法直接知道哪段属于哪章哪节。本系统用 9 种检测方法从纯文本中自动恢复层次。

### 核心机制

**9 种章节检测方法**：

| # | 方法名 | 匹配模式 | 置信度 |
|---|--------|---------|--------|
| 1 | standard_chapter | `第X章/篇/部分/单元` | 0.98-0.99 |
| 2 | standard_section | `第X节` | 0.98-0.99 |
| 3 | experiment_heading | `实验X` | 0.95-0.98 |
| 4 | introduction_heading | `绪论`/`绪言` | 0.95-0.98 |
| 5 | classic_heading | 经典文本 `⟨text⟩第X` | 0.95-0.98 |
| 6 | metadata_path | Chunk 元数据中的标题路径 | 0.99 |
| 7 | source_body_heading | Markdown 正文中最近的标题 | 0.98 |
| 8 | source_catalog_section | 目录→章节逆映射 | 0.94 |
| 9 | carry_forward | 无标题时继承上一个已知章节 | 0.91 |
| 10 | section_sequence_fallback | 完全无法解析 → `UNRESOLVED_{id}` | 0.35（需人工复核） |

**中文数字解析**：自定义解析器，将"一、二、三...十、百、千、万"及复合数字"二十五"正确转为 `int`。

**目录逆向恢复**：从 Markdown 前置 ToC（目录）中提取章节名称，反向构建章→节映射表，再通过节名匹配确认归属。

**同名节合并**：同一章内相同规范化标题的节自动合并为 `logical_section`，避免"概述"、"小结"等通用标题造成的歧义。

**产出规模**：9,035 个章节点 + 73,170 条 Chunk-章节关联，覆盖全部中医药教材。

### 技术创新

- 9 种方法互补覆盖：从结构化匹配到无结构回退，确保没有文本被遗漏
- 每个检测结果带置信度：低置信度标记 `needs_review`，供人工审核优先处理
- 中文数字解析不依赖词典：支持任意合法的中文数字组合
- 目录→章节逆映射：充分利用 PDF 中残留的 ToC 信息
