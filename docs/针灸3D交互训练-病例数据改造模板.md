# 针灸 3D 交互训练病例数据改造说明

> 用途：提供给病例数据整理人员、针灸专业审核人员和前后端开发人员。
>
> 本文只说明病例数据如何调整，不要求修改穴位拼音映射表，也不直接修改现有病例文件。

## 1. 改造目标

现有病例已经包含标准穴位、进针深度、进针角度描述和留针时间，但缺少与 3D 人体模型稳定关联、可供程序直接判断的结构化字段。

本次改造目标：

1. 将病例标准穴位关联到 GLB 中对应的穴位节点。
2. 将进针角度从自由文本补充为“直刺、斜刺、平刺”三分类。
3. 保留原有医学描述，供正确答案和教学反馈展示。
4. 为三维位置判断补充允许偏差。
5. 区分常规针刺、刺络、刺络拔罐等不同操作。
6. 保持对现有二维数据和旧程序的兼容。

## 2. 不需要修改的文件

穴位拼音映射表继续只负责以下关系：

```text
拼音 ↔ 中文穴位名 ↔ GLB 原始节点名
```

映射表中不要加入：

- 进针角度
- 进针深度
- 留针时间
- 病例评分阈值
- 病例治疗方案

以上内容均属于病例标准，应保存在病例数据中。

## 4. 第一版最小新增字段

每个 `standardAcupoints` 项新增以下字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | ---: | --- |
| `pinyin` | string | 是 | 与穴位拼音映射表一致的基础拼音 |
| `modelNodeName` | string | 是 | GLB 中用于定位标准穴位的节点名 |
| `procedureType` | enum | 是 | 本穴位对应的操作类型 |
| `insertionType` | enum/null | 条件必填 | 常规针刺时填写直刺、斜刺或平刺 |
| `directionDescription` | string | 否 | 如“向掌心”“向上”“沿经脉方向” |
| `positionTolerance` | object | 是 | 用户针位与标准节点之间的允许误差 |

### 4.1 `procedureType` 枚举

```text
needling          常规针刺
pricking          刺络
pricking_cupping  刺络拔罐
```

### 4.2 `insertionType` 枚举

```text
direct      直刺
oblique     斜刺
transverse  平刺
```

非普通针刺操作，例如刺络拔罐，可将 `insertionType` 设为 `null`。

- `positionTolerance.value` 在专业人员和模型人员确定前填写 `null`。
- 当容差为 `null` 时，程序不得生成三维位置分数。

## 8. 病例顶层建议新增模型版本

每个病例顶层建议增加：

```json
{
  "trainingModel": {
    "asset": "blender.yibiaozhu.glb",
    "version": "2026-07-29",
    "coordinateSystem": "glb-world"
  }
}
```

作用：

1. 明确病例标准基于哪个模型版本。
2. 防止以后替换 GLB 后坐标变化导致旧评分失效。
3. 支持旧训练记录回放和模型版本追踪。

## 10. 用户提交数据模板

用户操作结果应与病例标准分开保存，不要回写到病例文件。

  "caseId": "acup_00006",
  "modelVersion": "2026-07-29",
  "needles": [

## 11. 旧数据迁移规则

### 11.1 可以自动填充

- `pinyin`：根据中文穴位名查询穴位映射表。
- `modelNodeName`：根据映射表中的原始节点名填充。
- `procedureType`：普通针刺默认 `needling`。
- `insertionType`：可根据 `needleAngle` 文本初步转换。

文本转换建议：

```text
包含“直刺” → direct
包含“斜刺” → oblique
包含“平刺”或“横刺” → transverse
包含“刺络拔罐” → procedureType = pricking_cupping，insertionType = null
仅包含“刺络” → procedureType = pricking，insertionType = null
无法识别 → insertionType = null，标记人工复核
```

### 11.2 必须人工或专业复核

- 中文穴位名与 GLB 节点是否确实对应。
- 左右侧穴位应该关联哪个节点。
- `directionDescription` 是否准确。
- 三维位置允许偏差。
- 特殊穴位是否禁刺或慎刺。
- 深度和留针时间是否适用于当前病例与患者情境。

## 12. 数据验收规则

每个普通针刺穴位必须满足：

1. `pinyin` 非空。
2. `modelNodeName` 在当前 GLB 中存在。
3. `procedureType` 为 `needling`。
4. `insertionType` 为 `direct`、`oblique`、`transverse` 之一。
5. `needleDepth.min <= needleDepth.max`。
6. `retentionTime.min <= retentionTime.max`。
7. 深度和留针时间单位明确。
8. `positionTolerance.reviewStatus` 明确为 `pending` 或 `approved`。
9. 未审核容差时 `positionTolerance.value` 必须为 `null`，不得使用猜测值。

特殊操作穴位必须满足：

1. `procedureType` 为 `pricking` 或 `pricking_cupping`。
2. `insertionType` 为 `null`。
3. 具有清晰的原始操作说明。
4. 前端不得按普通针刺流程评分。

## 13. 第一版实施范围

第一版只要求补齐：

```text
pinyin
modelNodeName
procedureType
insertionType
directionDescription
positionTolerance（未审核时 value=null）
trainingModel
```

继续保留现有：

```text
needleDepth
needleAngle
retentionTime
coordinates
imagePath
```

第一版不要求：

- 给斜刺填写精确几何角度。
- 给方向填写三维向量。
- 删除旧二维坐标。
- 修改穴位拼音映射表。
- 在专业审核前填写位置容差数值。

## 14. 结论

病例数据负责“这个病例应该怎么扎”；穴位映射表只负责“这个穴位在模型中叫什么”。两者必须分离。

第一版应优先完成病例穴位与 GLB 节点关联，以及直刺、斜刺、平刺三分类。精确方向和三维容差必须经过专业审核后再进入真实评分。
