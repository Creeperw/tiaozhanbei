# 上传处理收敛：第一阶段

## 范围

本阶段仅统一底层解析与教材、考纲模型传输，不修改API、前端入口、用户归属、审核/激活条件或业务数据布局。

### 共用文件解析

`backend/competition_app/services/document_parsing.py` 提供 `parse_mineru`：

- 校验服务端配置，执行交付组件中的 `parse_question_pdf.py`，不修改外置组件。
- 返回 Markdown、源产物路径、输出目录、运行编号及解析方式。
- 保留PDF分卷输入顺序、运行目录和已有恢复产物；聚合Markdown在重试时排除自身。
- 仅对解析器固定的下载失败诊断按配置重试；错误不回显子进程正文、密钥或签名链接。
- 不承担鉴权、用户目录分配、知识点生成或业务发布。

| 调用方 | 保留行为 |
| --- | --- |
| `TextbookImportService._run_mineru` | 分卷、页码偏移、教材聚合文件、目录和书架发布 |
| `UserSyllabusService._mineru_markdown` | 考纲聚合文件、结构化、映射与原激活行为 |
| `KnowledgeDeliveryBackend._parse_pdf_to_markdown` | 正式题目/考纲导入原有全部Markdown读取规则 |
| `MinerUPdfParser.parse` | 旧后端导入时配置、个人题库与管理员流程 |

正式个人知识资料导入仍经完整外置流水线及现有 `upload_pipeline_runner.py`，不另做一次MinerU解析，不改变个人写锁、高水位编号、删除或重建。

### 共用模型传输

`backend/competition_app/llm/upload_json_client.py` 由教材与考纲服务共用：

- 复用 `upload_provider.py`，同一次调用的重试使用同一个OpenCode会话，不同调用隔离。
- 参数兼容重试不更换端点、模型或凭据；永久性HTTP错误不做无效重试。
- 有限重试暂时性故障、空输出及无效JSON；保留业务错误类型与业务提示词。
- 视觉配置以地址、模型、密钥整体选择，部分配置拒绝混搭。只有默认视觉模型名而无视觉地址/密钥时，沿用完整聊天配置；这不代表聊天模型已验证支持图像。
- 教材仍保留现有目录降级逻辑；考纲仍使用原聊天模型配置。配置真实视觉服务及Live能力验收尚未完成。

个人题目模型提取仍使用已有 `health_llm.py`（已复用服务会话头），管理员的结构化题目抽取策略不变，未将两种抽取语义强行合并。

## 验证与后续

新增解析器与JSON客户端测试均使用本地临时目录、子进程替身或HTTP MockTransport，不访问在线模型，不写业务数据。

验证覆盖：产物筛选、恢复时不重复聚合、分卷页码、失败脱敏、配置隔离、重试、业务错误适配及原上传流程回归。

任务持久化、任务查询归属补齐、前端统一上传面板属于后续阶段；当前API返回与页面入口保持原样。离线通过不等于线上验收完成。
