# 首页与学习路径交互设计

## 目标

让用户从首页首次进入学习路径时先明确资格考试目标，并在学习路径中清晰区分路线来源与呈现方式；同时修复头像菜单进入收藏夹、笔记本后的返回来源。

## 已确认交互

1. 首页主视觉区只保留“开始学习”，移除“多智能体助教”按钮。
2. 账号没有服务端学习目标时，首次点击“开始学习”弹出资格考试选择框；保存后不再自动弹出。弹窗允许取消，保存失败时留在弹窗内提示。
3. 学习路径提供两组层级不同的切换：
   - 路线来源：`经典路径 | 个性化路径`
   - 呈现方式：`学习阶段 | 学习路径`
4. 默认展示经典路径的“学习阶段”；“学习阶段”按钮位于“学习路径”左侧。
5. 点击阶段卡后切换到“学习路径”，并打开该阶段对应的教材节点。
6. 学习路径标题旁提供轻量“学情调研”按钮，打开可回填既有答案的调研弹窗。保存后刷新路线数据。
7. 顶部“考试类别”下方用小字展示当前类别，长名称截断但保留完整可访问名称。
8. 从头像菜单进入收藏夹或笔记本时携带进入前的完整页面意图，左上角返回到真实来源页。

## 数据与状态

- 是否首次选择以 `GET /api/personalization/learning-target` 返回的 `target` 是否为空为准，不使用 `localStorage`。
- 资格考试目录沿用 `GET /api/v1/qualification-targets`，保存沿用现有 `saveLearningTarget`。
- 经典路径沿用 `loadClassicLearningRoute`；个性化路径沿用 `loadPlannedLearningPath`。
- 学情调研复用 `OnboardingSurveyPanel` 的加载与保存能力，并增加适合站内弹窗的退出文案。
- 返回来源由 `App` 将当前 `pageIntent` 传给 `AppShell`，头像快捷入口把它写入目标页的 `returnTo`。

## 异常与空状态

- 资格考试目录或保存失败：弹窗显示错误和重试能力，不进入学习路径。
- 个性化路径未生成：显示现有后端返回的可用性说明，并保留“学情调研”入口。
- 路线切换请求失败：只影响当前路线区域，不清空另一路线的已加载状态。
- 返回来源缺失：保持现有“返回训练工坊”兜底。

## 验证

- 组件测试覆盖首次弹窗、已选用户直接进入、取消与保存失败。
- 组件测试覆盖按钮顺序、默认阶段视图、经典/个性化请求和阶段定位。
- 组件测试覆盖顶部当前类别提示与收藏夹、笔记本的 `returnTo`。
- 运行相关 Vitest、生产构建、目标文件 ESLint 与 `git diff --check`。
