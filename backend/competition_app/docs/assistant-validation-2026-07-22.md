## 已修复缺陷

1. 删除 Planner 正常路径的闲聊规则提前返回；“你好”等输入现在也必须调用 Planner 模型。
2. `casual_response` 成为 Planner 输出契约的一部分，最终用户回复直接使用模型结果，不再调用
   固定 `_casual_response()` 模板。
3. 新增 `CHAT_MODELS` 候选列表，顺序为：`qwen3.7-flash`、`qwen3.7-max-preview`、
   `glm-5.2`、`qwen3.7-flash-2026-07-15`、`qwen-plus`。
4. 新增配额/限流、模型不存在、provider 不兼容、超时/网络异常、持续 5xx、空响应、空流及
   非法 JSON 的错误分类和候选切换。
5. `.env` 与 `.env.local` 已加入忽略规则，现有本地文件未删除。
6. Planner 增加模型输出后的业务冲突检查：问候、感谢或告别与长期/短期/今日任务、知识讲解、
  组卷、学习规划、学习卡或直接学习资源并存时，模型不得用 `casual_conversation` 静默吞掉
  真实任务。
7. Planner 的 Pydantic 业务契约已纳入候选尝试边界；首选模型返回语法正确但业务无效的 JSON
  时，会尝试下一候选。内部 validator 不会进入供应商请求、运行事件、trace 或快照。
8. 候选和同模型 JSON repair 的流式增量先在本地缓存，只在对应尝试最终成功后提交；失败尝试
  仅保留诊断信息，不再污染用户可见 SSE。
9. `ModelTraceRecorder`、OpenAI-compatible transport 元数据和 Failover transport 元数据改为
  当前异步上下文隔离；候选活动索引和历史更新增加并发锁，切换历史限制为最近 100 条。
10. `chat_models` 作为候选配置真源；直接构造 `Settings` 时会去重、校验非空并同步兼容字段
   `chat_model`，正式容器始终使用规范化候选列表。
11. 诊断阶段不再无条件信任历史持久化的教材、阶段和书目信息；旧路线只有与当前可信路线
  一致时才会复用，否则回退到当前路线的首个可信阶段，避免跨路线污染新规划。
12. 面向用户的工作流正文会过滤 Agent 名称、routing、压缩状态及确定性依赖等内部说明；
  模糊规划使用自然语言解释需要补充的信息，SSE 失败事件只发送友好文案，技术异常仍保留
  在运行状态和 trace 中供排障。
13. 客观题判分在服务端统一规范化答案格式；前端提交的 `C. 阴阳转化` 与标准答案 `C`
  视为等价，同时保留多选完整正文的兼容能力。
